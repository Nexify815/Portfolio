Nexisploit: All-in-One Android ADB Toolkit

A command-line toolkit for working on Android devices over ADB, scrcpy and Metasploit. One typed number, 165 tools, and read-only security checks built in.

The problem

Work over an Android phone from a laptop normally means raw adb incantations and a pile of half-finished scripts. The toolkit that already existed had grown wide rather than usable: 26 hubs on the front page, most of them shells over a shell, an external audit binary nobody else had installed, and state-changing actions one accidental number away from wiping data.

What I built

An extended version of the open-source PhoneSploit Pro toolkit, rebuilt into Nexisploit: 165 tools across 15 verb-based groups, a live device status in the menu, a 12-section security posture report, four continuous monitors and reports that run entirely against a connected phone.

01

Everything two keystrokes deep

15 groups, one numbered menu, six most-recent tools pinned on top, plus fuzzy search and an always-visible device status.

02

Native security checks

14 read-only checks from patch level to verified boot, reimplemented against adb; no external audit binary needed.

03

Remote camera

Discovery, live view, recording, motion detection and diagnostics, with sizes probed from scrcpy instead of guessed.

04

Continuous monitors

Performance dashboard, Wi-Fi monitor, route tracker and notification wall; one batched adb call per tick.

05

HUD overlay

An OpenCV heads-up display drawn over the mirrored screen: element boxes, touch points and a live telemetry panel.

06

Reports and maintenance

Battery wear, screen time, disk doctor, targeted cache cleanup; dry-run first, typed confirmation before anything deletes.

Runs on a laptop; everything the tool needs the phone already has, beyond developer options and USB debugging.

Decisions that mattered

Numbered menu, not a cursor UI

The arrow-key frame drifted and overflowed depending on prior output, so the toolkit dropped cursor escapes and scrolls like any CLI. Group first, number second.

Group by verb, not object

A tool that pushes a file from this PC is a file operation even when the file is a photo. Host-side work gets its own group, so the menu reads verbs, not nouns.

Native audits, no HARDAX

The 98 references to an external audit binary were reimplemented as 14 getprop/settings reads with OK, REVIEW and RISK, so the checks run anywhere adb runs.

Guards where state changes

Destructive handlers ask for a typed YES, cleanup tools dry-run first, and read-only diagnostics never reach the device's state.

Outcome

A 165-tool ADB toolkit in which the most common phone tasks are never more than two keystrokes away, the read-only audits run anywhere adb runs, and the sharp edges are behind confirmations. Extended from PhoneSploit Pro by Azeem Idrisi, released under the GNU GPL v3.
