The problem

Downloads folders rot because filing has to happen at the exact moment you least want to do it. Filenames rarely tell you what a file actually is, either.

What I built

A filesystem service that watches a folder, detects new files and browser temp-name to final renames, and waits until a file's size has been stable for a few seconds. It then identifies the file by reading PDF text to tell an invoice from a statement from a contract, and extracts the date and vendor to build a clean name.

01

Wait-until-done

Partial .crdownload and .part files are ignored.

02

Content intelligence

PDF text decides the category and supplies the date and vendor for names like 2026_July_Acme_Power_Electric_Bill.pdf.

03

Rules-driven

Categories, keywords and extensions live in a commented config.yaml, so no code changes are needed to retune it.

04

Quiet by default

With an optional Windows tray icon and logon auto-start.

Safety model

Nothing is ever destroyed, and every move can be reverted.

Atomic same-volume moves

Cross-volume moves copy, verify a SHA-256 hash, then delete the source.

Uncertain files are never touched

So they stay in the watched folder.

Every action is logged with an id

--undo <id> restores it, deduping instead of overwriting.

--dry-run

Previews every decision without touching a file.
